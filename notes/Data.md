# Data

**Summary**: Notes on datasets, data portals, data formats, labeling tools, pipelines, and storage and distribution practices.
**Last updated**: 2026-08-24

- [Source Cooperative](https://source.coop/): The Cooperative Data Publishing Utility - Data publishing at any scale for everyone. "A nonprofit data publishing utility built on commodity cloud object storage", a Radiant Earth project. Data is served over plain URLs and S3-compatible storage so it works with existing tools instead of a bespoke portal or API. Aimed at data engineers, scientists and researchers who would rather not run infrastructure, with flat volume-based pricing, publishers keeping ownership, open formats to avoid lock-in, and an explicit stance against institutional capture. It also hosts the Fields of the World outputs; see [[Agriculture]]. *Keywords: Radiant Earth, data publishing, S3, open formats, nonprofit, cloud object storage*
  - Related: [[Benchmark_Datasets]], [[Geospatial_Platforms]]

- [STAC Index](https://stacindex.org/): Stac Catalogue similar to GEE Catalogue. "Here you can find STAC Catalogs, APIs, Software and Tools. You can also add your own data and tools to the list." A directory of where to find SpatioTemporal Asset Catalog endpoints across dozens of providers, and the starting point for discovering which STAC APIs exist and what they hold. The value of STAC itself is that one query pattern (location, time range, collection, metadata filters) works identically against NASA's catalog, Microsoft Planetary Computer, AWS Earth Search or anything else STAC-compliant. *Keywords: STAC, catalog directory, API discovery, interoperability, metadata standard, endpoints*
  - Related: [[Python]], [[Benchmark_Datasets]]

- [geoai-datacubes](https://github.com/buckai-observatory/geoai-datacubes): Acquisition, harmonization, and pre-processing of AI-ready multimodal satellite data cubes. "Ready-to-use pipelines that download satellite imagery for any region and time you choose, then pre-process it into AI-ready 'data cubes'." Pulls from 26 satellite missions (Sentinel-1/2, Landsat, NAIP, PlanetScope, MODIS and more) through four interchangeable providers, handles cloud masking, normalisation, tiling and augmentation, fuses missions onto common grids, and splits datasets with spatially-aware strategies to avoid leakage, feeding PyTorch with on-the-fly tile sampling. From the BuckAI Observatory at Ohio State (Jain, Radhakrishnan, Roy Chowdhury, Hsu, with Moortgat as PI). MIT. *Keywords: data cubes, AI-ready, multimodal, spatial data leakage, PyTorch sampling, Ohio State*
  - Related: [[Foundation_Models]], [[Code_Repositories]], [[Python]]

- [Planet Data API introduction notebook](https://github.com/planetlabs/notebooks/blob/master/jupyter-notebooks/api_guides/data_api/planet_data_api_introduction.ipynb): Planet. Part of "interactive notebooks from Planet Engineering", a repository teaching how to work with Planet's APIs and imagery archive. Covers API authentication and use, analysis with satellite imagery, remote sensing technique, the Insights Platform, and the Sentinel Hub Python SDK. Apache-2.0. *Keywords: Planet Labs, data API, jupyter notebooks, authentication, PlanetScope, API guide*
  - Related: [[Python]], [[Code_Repositories]]

- [Annotation of datasets for deep learning applied to satellite and aerial imagery](https://github.com/satellite-image-deep-learning/annotation?tab=readme-ov-file#annotation-tools-with-geotiff-support): Annotation of datasets for deep learning applied to satellite and aerial imagery. A reference guide from the satellite-image-deep-learning organisation covering annotation formats (PASCAL VOC, COCO-JSON, GeoJSON, YOLO) and, most usefully, which tools handle GeoTIFF directly, since "relatively few annotation tools support Geotiffs directly". Lists LabelMe, Kili, Labelbox, Supervisely, Microsoft's satellite-imagery-labeling-tool, and AI-assisted newcomers SCANEO and SentinelLabel, organised into formats, GeoTIFF-native tools, open source, cloud services, and conversion utilities. Apache-2.0. *Keywords: annotation tools, GeoTIFF support, labeling formats, COCO YOLO GeoJSON, curated list, training data*
  - Related: [[Code_Repositories]], [[Benchmark_Datasets]], [[Land_Cover]]

- [Open Source Labeling for Sentinel-2: Why I Built SentinelLabel](https://medium.com/@m.saleh.saudi/open-source-labeling-for-sentinel-2-why-i-built-sentinellabel-c9023eca7236): Open Source Labeling for Sentinel-2: Why I Built SentinelLabel. M. Saleh Saudi's write-up of [SentinelLabel](https://github.com/msalehsaudi/SentinelLabel), "a tool for easy geospatial annotation" that streams Sentinel-2 from S3, auto-segments an area of interest into superpixels, and lets annotators classify the resulting polygons with number-key hotkeys, exporting GeoPackage. It targets four failure modes of conventional labeling: temporal mismatch when tracing over Google Maps basemaps, subjectivity in hand-drawn polygons, area-based class imbalance, and the sheer manual cost — claimed to compress 8–16 hours of polygon drawing into 10–30 minutes per km². Built on FastAPI with async S3 streaming, scikit-image Felzenszwalb segmentation, K-Means, geopandas / rioxarray / rasterio, and a React 18 plus Leaflet front end. MIT licensed. *Keywords: annotation tool, Sentinel-2, superpixel segmentation, label quality, GeoPackage, FastAPI*
  - Related: [[Code_Repositories]], [[Land_Cover]], [[Benchmark_Datasets]], [[Python]]

- [From Satellite Data to Machine Learning: Simplifying Data Pipelines with a Cloud-Based Approach](https://medium.com/@tahjudil.witra/from-satellite-data-to-machine-learning-simplifying-data-pipelines-with-a-cloud-based-approach-2c810cf30b2c): From Satellite Data to Machine Learning: Simplifying Data Pipelines with a Cloud-Based Approach. Tahjudil Witra walks through a modular pipeline that turns raw satellite imagery into model-ready batches without committing to a rigid, hard-to-scale workflow. It starts from a STAC search — querying time, location and product type in one place — then chains Xarray, Zarr and xbatcher so that large downloads and fixed preprocessing steps largely go away. A hands-on notebook (`01_Satellite_Data_Pipeline.ipynb`) lives in the author's ModularGeoFM repository. A follow-up article from January 2026 benchmarks two pipeline configurations on real imagery, measuring GPU utilisation during training to quantify the trade-offs. *Keywords: STAC, Xarray, Zarr, xbatcher, data pipeline, GPU utilisation*
  - Related: [[Python]], [[Foundation_Models]], [[Remote_Sensing]]

- [Africa GeoPortal - powered by Esri](https://www.africageoportal.com/): Interesting Portal. An open mapping community for Africa, run by Esri, built to lower the barrier to geospatial technology on the continent. Single users get free access to ArcGIS Online, the Living Atlas, apps and analytical tools such as Collector, Survey123, StoryMaps and Insights, plus a large slice of Esri's e-learning material. Its three pillars are data, capabilities, and a learning center, and much of its value sits in community-contributed data gathered at local, national and continental level. *Keywords: Africa, Esri, ArcGIS Online, open data portal, community data, GIS tools*
  - Related: [[Remote_Sensing]], [[Urban_Planning]], [[Learning_Resources]]

## Cross-cutting notes

Cloud-native geospatial formats — GeoParquet, COG, GeoZarr — and STAC metadata standards come up in the Earth embedding interoperability discussion in [[Remote_Sensing]]. The Groundsource flood event dataset in [[Climate_Change]] is an example of a large open dataset distributed as a single Parquet file. Access terms vary widely across products: the TanDEM-X FNF50 map in [[Forestry]] is restricted to scientific use, while the Forest Data Partnership catalog is open through [[Google_Earth_Engine]] and the Copernicus Land Monitoring Service publishes its phenology suite openly, see [[Vegetation_Phenology]].

Labeled training data is its own bottleneck: the Lacuna Fund funds equitable labeled agricultural datasets for low- and middle-income contexts, and the M3DRS multi-modal dataset was released unlabeled for self-supervised pretraining — see [[Agriculture]] and [[Remote_Sensing]].

Labeled benchmarks are indexed separately on [[Benchmark_Datasets]], which groups them by what they test — pretraining corpora, segmentation, object extraction, multimodal and time series.
